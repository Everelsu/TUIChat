# null_terminal

Чат в локальной сети: сервер на Rust, клиент для терминала и веб-клиент для
телефона. Оба клиента говорят на одном протоколе — сервер не знает, кто на том
конце.

```
┌──────────────┐   WebSocket (JSON)   ┌──────────────┐   WebSocket (JSON)   ┌─────────────┐
│ null_terminal│ ──────────────────── │    Сервер    │ ──────────────────── │ Браузер     │
│ (терминал)   │                      │  axum+tokio  │   он же отдаёт HTML  │ (телефон)   │
└──────────────┘                      └──────────────┘                      └─────────────┘
```

## Скачать готовое

Собранные архивы лежат в [Releases](../../releases): внутри `null_terminal`
(клиент, он же сервер по `--host`) и `server` — на случай, когда комната должна
жить без открытого терминала. Ни рантайма, ни установщика: распаковал и
запустил.

Архивы собирает GitHub Actions по тегу `v*` — под Windows, Linux и macOS. Тот
же workflow можно запустить руками из вкладки Actions, чтобы получить сборку из
ветки, не заводя тег.

## Быстрый старт

Сервер (слушает `0.0.0.0:8080`, адрес меняется переменной `CHAT_ADDR`):

```bash
cargo run -p server
```

Терминальный клиент — ник спросит на главном экране:

```bash
cargo run -p null_terminal
```

Можно и сразу, минуя экран входа:

```bash
cargo run -p null_terminal -- --nick alice --room general
```

Веб-клиент: открыть в браузере `http://localhost:8080`. Ссылка вида
`http://localhost:8080/?room=rust` зовёт сразу в нужную комнату.

## Главный экран

Первое, что видно, — не форма из трёх строк, а четыре вкладки. Всё, ради чего
клиент открывают, лежит на виду, а не за командой со слэшем:

| Вкладка | Что там |
| --- | --- |
| `◆ войти` | ник, адрес сервера и живой список комнат с числом людей |
| `✦ поднять` | свой сервер прямо в этом окне: ник, комната, порт |
| `◐ вид` | тема, картинки в ленте, колонка людей, перезапуск в терминале |
| `♪ звук` | динамики, микрофон, звоночек при упоминании и его громкость |
| `? справка` | клавиши и команды — то же, что по `F1` |

Клавиши здесь не спорят друг с другом: `Tab` всегда листает вкладки, `↑`/`↓`
всегда ходят по строкам (сверху вниз по полям и дальше в список комнат), `←`/`→`
двигают курсор в поле, а на вкладке «вид» — листают значение. `Enter` делает то,
что написано на кнопке внизу вкладки.

Сервер, поднятый на вкладке «поднять», не уводит с экрана, пока не встанет:
занятый порт — обычное дело, и сказать об этом надо там же, где его набрали, а
не красной строкой в пустой переписке.

На вкладке «звук» перечислены устройства, которые видит система. Выбор
применяется сразу и подтверждается звоночком — услышать, куда ушёл звук,
единственный способ убедиться, что выбрал те наушники. Запоминается имя
устройства, а не его номер: наушники втыкают и вынимают, и после перезапуска
третье устройство в списке — уже не то же самое. Если выбранного больше нет,
клиент молча возвращается к системному.

## Выход и возврат в меню

`Esc` — «назад», а не «выход»: он закрывает то, что открыто поверх (картинку,
поиск, цитату, выбор вложения), а из самой комнаты уводит обратно в меню. То же
делает команда `/menu`. Соединение при этом закрывается — висеть в комнате,
стоя в меню, значит показывать другим, что человек тут, когда его тут нет.
Переписка остаётся в памяти: вернувшись в ту же комнату, видно, на чём
остановились.

Закрывает программу только явное сочетание — `Ctrl+Q`, `Ctrl+C` или `Ctrl+D` —
и команда `/quit`. Промах по `Esc` не должен стоить разговора.

Всё главное делается одной подписанной клавишей — команды учить не нужно:

| Клавиша | Что делает |
| --- | --- |
| `F1` | справка |
| `F2` | записать голосовое, повторно — отправить |
| `F3` | послушать последнее голосовое, повторно — стоп |
| `F4` | отправить файл — любой, не только картинку |
| `F5` | сохранить присланное на диск |
| `F6` | открыть присланное системной программой |
| `F7` | выбрать вложение в ленте — не только последнее |

`F3`, `F5` и `F6` работают с последним вложением. Когда нужно старое —
`F7`: стрелки прыгают по сообщениям с вложениями (мимо всей болтовни между
ними), `Enter` делает то, что для этого вложения естественно — картинку
показывает, голосовое проигрывает, файл сохраняет. `F5` и `F6` там же работают
по выбранному. Это тот же механизм, что и выбор сообщения для ответа по
`Ctrl+R`, только ходит он по другим сообщениям.

По вложению можно просто **щёлкнуть мышью** — эффект тот же, что у `Enter`
после выбора.

Команды в TUI (и `/help` внутри клиента) — то же самое для тех, кому так
привычнее:

| Команда | Что делает |
| --- | --- |
| `/join <комната>` | перейти в другую комнату |
| `/rooms` | показать живущие на сервере комнаты |
| `/nick <ник>` | сменить ник |
| `/send` | выбрать файл в обзоре; `/send <путь>` — отправить сразу |
| `/rec` | записать голосовое, повторно — отправить |
| `/host [порт]` | поднять свой сервер и позвать друга |
| `/color <цвет>` или `/color <ник> <цвет>` | свой или чужой цвет, `-` сбрасывает |
| `/play` | проиграть последнее голосовое, `/stop` — остановить |
| `/save [путь]` | сохранить последнее вложение на диск |
| `/view` | показать последнюю картинку прямо в терминале |
| `/open` | открыть последнее вложение внешней программой |
| `/clear` | очистить историю на экране |
| `/quit` | выход |
| `//текст` | отправить сообщение, начинающееся со слэша |

Переписка собрана из четырёх частей: полоса состояния с комнатой, людьми и
связью, лента, поле ввода и строка подсказок. Сообщения одного автора идут одной
группой под цветной стойкой слева — по ней видно, где начинается и кончается
чужая речь, даже когда экран забит текстом целиком. Свежая реплика вспыхивает и
гаснет: глаз ловит именно появление.

Колонка с людьми (`Ctrl+P`) по умолчанию спрятана — разговору ширина нужнее, —
а в окне уже 72 колонок показывает, кто в комнате и кто прямо сейчас печатает.

Цвета заданы в RGB, поэтому терминалу нужен 24-битный цвет — он есть в Windows
Terminal, VS Code, iTerm2 и почти везде, кроме совсем старых эмуляторов. Тема
меняется на вкладке «вид» и переживает перезапуск: на разных обоях терминала
один и тот же фиолетовый читается по-разному, и человеку нужно уметь выбрать
различимый.

Клавиши:

| Клавиша | Что делает |
| --- | --- |
| `Enter` | отправить |
| `Tab` | дополнить команду в начале строки или ник, повторное — следующий |
| `Ctrl+O` | выбрать файл для отправки |
| `Ctrl+R` | ответить: стрелки выбирают сообщение, `Enter` подтверждает |
| `Ctrl+F` | поиск по истории, `Enter` и стрелки — по совпадениям |
| `Ctrl+P` | колонка с людьми справа |
| `↑` / `↓` | листать отправленное |
| `PgUp` / `PgDn`, колесо | прокрутка истории |
| `Ctrl+W` | стереть слово |
| `Ctrl+A` / `Ctrl+E` | в начало и конец строки |
| `Ctrl+U` / `Ctrl+K` | стереть до начала и до конца строки |
| `Esc` | закрыть картинку, поиск или цитату; иначе — выход в меню |
| `Ctrl+Q` | закрыть программу |

Справка по `F1` длиннее любого разумного окна: стрелки и `PgUp`/`PgDn` листают
её, а закрывает любая другая клавиша. Внизу рамки написано, сколько строк
осталось ниже, — обрезанный молча список читался бы как полный.

Перехват мыши нужен ради прокрутки колесом и ломает выделение текста — во всех
современных терминалах его возвращает `Shift` с зажатой мышью. Об этом сказано
и в самой справке: без подсказки это выглядит как поломка.

Сочетания работают и на русской раскладке. При ней `Ctrl+F` физически приходит
как «Ctrl+а», `Ctrl+R` — как «Ctrl+к», а `Ctrl+C` — как «Ctrl+с», то есть все
сочетания отваливаются ровно тогда, когда ими и пользуются: когда человек пишет
по-русски. Клиент приводит их обратно по раскладке ЙЦУКЕН.

При упоминании ника терминал подаёт звуковой сигнал: системных уведомлений
из TUI не показать.

## Картинки

В веб-клиенте картинку можно выбрать кнопкой `+`, вставить из буфера (`Ctrl+V`
после скриншота) или перетащить в окно. Подпись берётся из поля ввода, так что
картинка и комментарий уходят одним сообщением.

Из терминала файл отправляется клавишей `F4` (или командой `/send`): открывается
обзор каталога, файл выбирается стрелками, отсев по имени набирается прямо там.
Каталог запоминается — в следующий раз обзор откроется в нём же. Путь можно и
написать руками: `/send C:\фото\кот.png`.

Проще всего — **перетащить файл в окно**: терминал вставит его путь, а `Enter`
отправит сам файл, а не строку с путём. Отправлять путь текстом бессмысленно —
на том конце его открыть нечем, — поэтому строка, которая целиком является
путём к существующему файлу, уходит файлом. Кавычки вокруг пути, которые
дописывает Windows, снимаются сами.

Приглушать в обзоре нечего: отправить можно любой файл. Значок `◈` рядом с
именем говорит, что файл покажется прямо в переписке, — остальное придёт
строкой. Обратно вложение забирается клавишей `F5` (`/save [путь]`): без пути
файл ляжет в «Загрузки» под своим именем.

Голосовое записывается клавишей `F2`, повторное нажатие останавливает запись и
отправляет её. Внизу при этом тикает счётчик секунд. `F3` проигрывает
последнее голосовое и останавливает его повторным нажатием.

Пришедшее голосовое рисуется **столбиками формы волны**, а не строкой: по ним
сразу видно, где в записи речь, а где пауза, и насколько она вообще длинная.
Пока запись играет, столбики закрашиваются слева направо — получается заодно и
полоса прогресса. Длительность берётся из самого wav, а высота столбиков — из
пиковой громкости на каждом отрезке.

Пишется моно 16 кГц в wav: речи этого хватает с запасом, а пять мегабайт потолка
превращаются из тридцати секунд в две с половиной минуты. Wav выбран потому, что
браузеры играют его нативно, а opus нам не закодировать без C-библиотеки — то
есть записанное в терминале слышно везде, и это единственный формат, у которого
так получается.

В терминале картинка приходит строкой `[кот.png · 240 КБ]`. Команда `/view`
открывает её поверх переписки прямо в терминале, `Esc` закрывает; `/open`
отдаёт файл системному просмотрщику.

Если терминал умеет графику, картинки показываются **прямо в переписке**:
скачиваются сами и ложатся миниатюрой в десять строк под сообщением. Подпись
с именем и размером остаётся рядом, а `/view` открывает картинку во весь экран.

Миниатюры включаются везде, где терминал умеет настоящую графику: kitty, iTerm2
и sixel — то есть и в Windows Terminal тоже. В kitty и iTerm2 картинка привязана
к ячейкам буфера и при прокрутке едет вместе с текстом почти бесплатно; sixel
заставляет перерисовывать графику на каждый сдвиг, так что на длинной ленте это
заметнее. Если мешает — `inline_images = false` в конфиге, и останется строка
`[◈ кот.png · 240 КБ]` с показом по `Enter`.

Клиент при запуске спрашивает у терминала, что тот умеет. Если поддерживается
графика — kitty, iTerm2 или sixel, — фотография показывается фотографией.
Название протокола видно в нижней рамке просмотра: если там «полублоки», значит
терминал графику не поддержал.

Запасной путь — полублоки: символ `▀` делит ячейку пополам, верхняя половина
красится цветом символа, нижняя — цветом фона, так что одна строка даёт два ряда
пикселей. Разрешение скромное, зато работает везде, где есть 24-битный цвет.

Опрос терминала делается один раз, до запуска чтения клавиатуры: он пишет
escape-последовательность и ждёт ответ из того же stdin. И только если по обе
стороны настоящий терминал — иначе на Windows опрос уходит в бесконечный цикл.

Скачивание работает по http. Если сервер запущен с `CHAT_TLS=1`, терминал
скажет об этом и предложит `/open`.

Отправить можно **любой файл** — документ, архив, что угодно. Разница только в
том, как он придёт: картинка показывается, голосовое проигрывается, всё
остальное приходит строкой `[▤ отчёт.zip · 240 КБ]` и забирается по `F5`.

Тип определяется по содержимому файла, а не по имени и не по словам клиента.
Картинки (jpeg, png, gif, webp) и звук (webm, ogg, mp4, wav) сервер отдаёт для
показа, всё прочее — только на скачивание, заголовком
`Content-Disposition: attachment`. Это не формальность: файлы раздаются с того
же адреса, что и сам чат, и покажи мы в браузере присланный html или svg, он
получил бы доступ к странице переписки. Поэтому неизвестное содержимое всегда
`application/octet-stream` и всегда «сохранить», а не «открыть».

Ограничение по размеру — 100 МБ на файл; пустые файлы не принимаются. Потолок
задаёт сервер и называет его клиенту при входе в комнату: у чужого сервера он
может быть другим, и гадать по своей константе значит врать человеку.

Меняется он переменными окружения — обе считаются в мегабайтах:

| Переменная | По умолчанию | Что задаёт |
| --- | --- | --- |
| `CHAT_MAX_UPLOAD_MB` | 100 | потолок одного файла |
| `CHAT_MEDIA_CAPACITY_MB` | 512 | сколько всего вложений держать |

Совсем без потолка нельзя: файлы лежат в памяти сервера, и один гигантский
положил бы комнату. Когда место кончается, вытесняются самые старые вложения;
перезапуск сервера стирает их вместе с историей. Хранилище меньше одного файла
— недосмотр, а не настройка: сервер молча поднимает его до размера файла,
иначе не влезало бы вообще ничто.

## Разговор через интернет

Два домашних компьютера не соединяются напрямую, и дело не в протоколе. Друг
стучится на публичный адрес, пакет доходит до роутера, а тот смотрит: «порт
такой-то, а кому из устройств в квартире его отдать?» — правила нет, пакет в
мусор. Это NAT. Netcat здесь упирается ровно в ту же стену: он умеет открыть
сокет, но достижимость не решает никак.

Поэтому клиент не ждёт входящего соединения, а звонит наружу с обеих сторон
сразу: роутер видит исходящий пакет и сам открывает обратный путь. Этим
занимается [iroh](https://docs.rs/iroh) — QUIC, пробивание NAT, а если у
провайдера NAT строгий и пробить не вышло, трафик идёт через релей. Соединение
поднимается в обоих случаях, а ни VPS, ни проброса портов не нужно.

Хозяин комнаты запускает `/host` и получает в переписку **тикет** — строку из
52 знаков. Это открытый ключ его стороны, по нему друга и находят: домашний
адрес меняется, ключ нет.

```
друг из любой сети — пусть вставит это в «сервер»:
k7bqzn4x…
```

Друг вставляет тикет в поле «сервер» на вкладке «войти» — туда же, куда обычный
адрес. Клиент сам различает одно и другое: тикет состоит только из строчных букв
и цифр, а в адресе есть либо точки, либо двоеточие, либо слэши.

Тикет передаётся один раз и запоминается в настройках, так что в следующий раз
он уже подставлен. Совсем без него обойтись нельзя: чтобы найти друга в
интернете, надо знать, кого искать, — а без общего сервера с постоянным адресом
эту роль и играет ключ.

По трубе идёт тот же WebSocket с тем же JSON, поэтому комнаты, картинки,
голосовые и история работают одинаково — снаружи это просто труба, по которой
ходят байты. Вложения качаются отдельным запросом по той же трубе: адрес у них
тогда выглядит как `iroh://<тикет>/media/<id>`.

Трафик шифруется от конца до конца (QUIC + TLS 1.3), поэтому релей, если до
него дошло дело, видит только шифрованные байты. Входящие правила firewall не
нужны: обе стороны звонят наружу, а это Windows не блокирует.

Если вы в одной сети, туннель не обязателен — адрес вида `192.168.1.5:8080`
работает напрямую и быстрее.

## Список комнат

На вкладке «войти» рядом с формой виден список комнат, которые сейчас живут на
сервере, с числом людей в каждой. Стрелки `↑`/`↓` идут сверху вниз по полям и с
последнего спускаются в список, `Enter` заходит в выделенную комнату, а `Ctrl+R`
обновляет список. В веб-клиенте комнаты показаны так же — тап по комнате подставляет её имя
в поле. Смысл простой: чтобы позвать друга, не нужно пересылать ему адрес-код в
другом мессенджере — он открывает клиент, видит комнату и заходит.

Список берётся запросом `GET /rooms` (обычный JSON) с того же адреса, что и
переписка. Пустых комнат в нём нет: комната на сервере живёт, только пока в ней
кто-то есть, поэтому показывается ровно то, куда сейчас можно зайти. Уже из чата
тот же список доступен командой `/rooms`, а перейти — `/join <комната>`.

Список показывает комнаты **одного** сервера — того, чей адрес или тикет стоит в
поле «сервер». Через тикет он тоже работает: друг вставляет тикет, видит комнаты
и заходит, не спрашивая больше ничего.

## Разговор вдвоём без отдельного сервера

```bash
cargo run -p null_terminal -- --host
```

То же самое делается из уже открытого клиента командой `/host` — перезапускать
ничего не нужно. Клиент печатает в переписку адрес, который можно переслать:
собеседник вставляет его в поле «сервер» на вкладке «войти». Вставлять можно что
угодно узнаваемое — `192.168.1.5:8080`, `ws://192.168.1.5:8080/ws` или ссылку
на веб-клиент из браузера: клиент сам приведёт адрес к рабочему виду.

Порт меняется флагом `--port` или аргументом команды: `/host 9000`. Если он занят, клиент скажет об этом в обычном
терминале и не станет запускаться — молча уводить разговор на чужой сервер
хуже, чем отказаться.

Клиент поднимает сервер прямо в себе и печатает в переписку адрес, который
можно переслать собеседнику: он подключается через `--server ws://…`, а с
телефона открывает тот же адрес по http. Комната живёт, пока открыт терминал.

Отдельный процесс для разговора вдвоём — лишняя церемония: клиент и так умеет
всё, что нужно. Для постоянной комнаты сервер по-прежнему запускается сам по
себе.

## Звук

При упоминании ника клиент подаёт короткий сигнал. Он генерируется на месте, а
не берётся из файла: звуковой файл пришлось бы куда-то класть и как-то ставить
вместе с программой. Если звуковой карты нет, остаётся звоночек терминала.

`/play` проигрывает последнее голосовое прямо в клиенте, `/stop` останавливает.

**Важное ограничение.** Проигрываются wav, mp3, flac, vorbis и aac в mp4 —
всё, что умеет rodio. **Opus в этот список не входит**, а браузеры записывают
голосовые именно в него. Такое голосовое клиент честно откажется играть и
предложит `/open` — внешний проигрыватель с ним справится. Полноценная
поддержка требует libopus, то есть C-библиотеки в сборке, а от такой
зависимости мы уже отказались один раз ради chafa.

## Окно терминала

На Windows двойной клик по программе открывает её в conhost — окне, доставшемся
от cmd. Интерфейс здесь собран из 24-битного цвета и полублоков, и в conhost он
выглядит сломанным: человек решает, что сломана программа.

Поэтому клиент, запущенный двойным кликом, сам открывается заново в лучшем
терминале, который есть на машине, и закрывает исходное окно.

Своего эмулятора терминала мы не пишем. Движок Windows Terminal или WezTerm
лучше всего, что можно собрать сбоку, обновляется без нас и уже стоит у людей —
а самодельное окно стоило бы и картинок в ленте, и всей работы с вводом.

Запуск из уже открытого терминала не трогается: раз человек выбрал окно, ему
виднее. Двойной клик отличается от осознанного запуска не догадками по
переменным окружения, а числом процессов, привязанных к консоли: у окна,
созданного проводником, процесс один — наш собственный.

Поведение меняется настройкой `terminal` или флагом `--terminal`:

| Значение | Что делает |
| --- | --- |
| `auto` | по умолчанию: только после двойного клика |
| `always` | из любого старого окна, в том числе из cmd |
| `never` | никогда, что бы ни случилось |

Перезапуск не происходит, если окно уже приличное (Windows Terminal, WezTerm,
Alacritty, kitty, VS Code, ssh), если вывод перенаправлен в файл или канал, если
подходящего терминала на машине нет — и, конечно, в уже перезапущенном процессе.
Любая заминка означает «работать здесь»: остаться в кривом окне неприятно, а не
запуститься вовсе — уже поломка.

## Настройки

Клиент запоминает последний ник, комнату и адрес сервера после удачного входа —
запоминается то, что сервер принял, а не то, что ввели. Аргументы командной
строки эти значения перекрывают и ничего не перетирают.

Файл лежит там, где такие файлы принято искать: `%APPDATA%\null_terminal\config.toml`
на Windows, `$XDG_CONFIG_HOME/null_terminal/config.toml` или
`~/.config/null_terminal/config.toml` на остальных.

```toml
server = "ws://192.168.1.5:8080/ws"
nickname = "alice"
room = "general"
terminal = "auto"
theme = "charple"
sidebar = false
sound_output = ""
sound_input = ""
chime = true
volume = 1

[colors]
alice = "#7a5cff"
bob = "cyan"
```

`theme` — одна из четырёх: `charple` (сирень), `dolly`, `mint`, `ember`. Её же
и `sidebar` правит вкладка «вид»: там видно, как выбор выглядит, а не только как
называется. Пустые `sound_output` и `sound_input` означают «как в системе»,
`volume` — ступень громкости звоночка от 0 до 2; всё это правит вкладка «звук».

Файл прошлой версии из каталога `tuichat` читается один раз, если своего ещё
нет: программу переименовали, а ник, цвета и адрес сервера от этого теряться не
должны.

Цвета можно править руками или командой `/color`. Названия понимаются на обоих
языках (`cyan`, `бирюзовый`), а хранятся как `#rrggbb`. Сломанный файл не мешает
запуску: клиент берёт значения по умолчанию.

Туда же, в `crash.log`, пишутся падения. В TUI стандартный вывод занят
интерфейсом, поэтому иначе сообщение о панике исчезает вместе с закрывающимся
экраном, и понять, что случилось, нельзя.

## «Печатает…»

Пока собеседник набирает сообщение, внизу вместо подсказки идёт строка
«bob печатает» с бегущими точками; в браузере — над полем ввода.

Сигнал одноразовый: отдельного «я перестал печатать» в протоколе нет, строка
гаснет сама через четыре секунды. Так не приходится думать про потерянные
отмены. Клиент шлёт сигнал не чаще раза в две секунды, а сервер отбрасывает всё
чаще раза в секунду — клиент с ошибкой не должен заливать этим комнату.

## Ответы на сообщения

В терминале `Ctrl+R` открывает выбор сообщения, стрелки ходят по репликам,
`Enter` подтверждает — над полем ввода появляется цитата, `Esc` её снимает.
В браузере достаточно щёлкнуть по нику (по всему сообщению — нельзя, иначе
не выделить текст мышью).

Клиент отправляет только идентификатор исходного сообщения; цитату сервер
собирает сам из истории комнаты. Иначе ничего не стоило бы приписать человеку
слова, которых он не писал. Если исходное сообщение уже вытеснено из истории,
ответ уходит без цитаты — терять из-за этого сам ответ было бы обидно.

## Голосовые

Кнопка `●` в веб-клиенте начинает запись, повторное нажатие отправляет её;
запись сама останавливается через две минуты. Формат выбирает браузер: Chrome
пишет webm, Firefox — ogg, Safari — mp4, сервер понимает все три.

Микрофон браузеры дают только по https, поэтому для записи с телефона нужен
`CHAT_TLS=1` — по `http://192.168.x.x` кнопка честно скажет об этом.

В терминале голосовое выглядит как `[голосовое.webm · 42 КБ]` и открывается
через `/open`.

## HTTPS

По умолчанию сервер работает по http. Чтобы включить https:

```bash
CHAT_TLS=1 cargo run -p server
```

При первом запуске в каталоге `tls/` появится самоподписанный сертификат,
выписанный на `localhost` и на все локальные адреса машины. Браузер один раз
спросит подтверждение — это нормально для самоподписанного сертификата.
Удалите каталог, чтобы выпустить его заново (например, после смены сети).

Это понадобится, если захочется микрофон, камеру или уведомления: браузеры дают
их только в защищённом контексте, и по `http://192.168.x.x` они не работают
вообще.

## С телефона по Wi-Fi

Телефон и компьютер должны быть в одной сети. Узнать адрес компьютера:

```bash
ipconfig
```

Нужна строка «IPv4-адрес» вида `192.168.x.x`. Впрочем, сервер печатает нужный
адрес сам при запуске — строкой «с телефона». На телефоне открыть
`http://192.168.x.x:8080`, веб-клиент отдаёт тот же сервер, отдельно ничего
поднимать не надо.

Если страница не открывается, почти всегда дело в брандмауэре Windows: при
первом запуске он спрашивает, разрешить ли программе приём подключений, и надо
поставить галочку **частные сети**. Если окно уже было закрыто, разрешение
добавляется в «Защитник Windows → Брандмауэр → Разрешение взаимодействия с
приложением».

Для доступа из интернета нужен либо проброс порта на роутере, либо VPS с
публичным адресом. Протокол от этого не меняется — меняется только адрес,
который передаётся клиенту.

## Устройство

| Каталог   | Что там                                                        |
| --------- | -------------------------------------------------------------- |
| `common/` | типы протокола и проверка ввода — общие для сервера и клиентов  |
| `server/` | комнаты, рассылка, раздача веб-клиента                          |
| `null_terminal/` | терминальный клиент: `app` (состояние), `net` (связь), `ui/` |
|           | (отрисовка) и `theme` — палитра, градиенты и мелкая графика     |
|           | плюс `launcher` — перезапуск в нормальном терминале             |
|           | и `tunnel` — соединение через интернет в обход NAT              |
| `web/`    | веб-клиент: HTML, CSS и JS без сборки и зависимостей            |

Отрисовка разложена по экранам: `ui/home` — вкладки, `ui/chat` — переписка,
`ui/feed` — превращение реплик в строки, `ui/overlay` — окна поверх, а
`ui/widgets` — вкладки, плашки, кружки и бегунки, из которых собрано и то, и
другое. Логики там нет никакой, кроме переноса строк и подсветки: `update` —
обычная функция без ввода-вывода, поэтому поведение клиента проверяется
юнит-тестами, а не глазами в терминале.

Файлы из `web/` вшиты в бинарь сервера через `include_str!`: сервер запускается
из любого каталога и переносится одним файлом. Цена — после правки вёрстки
нужна пересборка сервера.

## Протокол

JSON поверх WebSocket на `/ws`. У каждого сообщения есть поле `type`.

Клиент → сервер: `join`, `chat`, `leave`, `ping`.
Сервер → клиент: `welcome`, `user_joined`, `user_left`, `chat`, `error`, `pong`.

Файлы по сокету не ходят: `POST /upload?name=<имя>` с телом-байтами возвращает
описание вложения, и в `chat` едет только его `attachment` — идентификатор.
Имя, размер и тип клиент не сообщает: их сервер знает сам, иначе подпись под
чужой картинкой подделал бы кто угодно. Отдаётся файл по `GET /media/<id>`.

Список комнат тоже не по сокету: `GET /rooms` отдаёт
`[{"name":"rust","users":2}]`. Отдельным запросом — потому что список нужен на
главном экране, до всякого `join`, а веб-клиенту его удобно забрать обычным
`fetch`. Пустых комнат в ответе нет: комната живёт, только пока в ней кто-то
есть.

Что стоит знать, если писать третий клиент:

- Первым сообщением обязан быть `join`, иначе через 10 секунд сервер закроет
  соединение. На неудачный `join` (занятый ник) соединение не рвётся — можно
  спросить у человека другой ник и попробовать снова.
- В ответ на `join` приходит `welcome` с последними репликами комнаты. У каждой
  есть `id`: после переподключения история накладывается на уже показанное, и
  клиент обязан отбрасывать дубли по нему. История живёт, пока в комнате есть
  хоть кто-то, — опустевшая комната удаляется вместе с перепиской.
- `error` несёт машиночитаемый `code`. `nickname_taken`, `invalid_nickname` и
  `invalid_room` переподключением не лечатся, остальные — временные.
- Время (`ts`) ставит сервер, в UTC и миллисекундах. Переводить в местное —
  забота клиента.
- Сообщения однострочные: переводы строк сервер схлопывает в пробелы,
  управляющие символы вырезает.
- Простаивающее соединение рвут роутеры молча, поэтому клиенты раз в 30 секунд
  шлют `ping` и ждут `pong`.

## Устойчивость

Что сделано, чтобы клиент и сервер не падали:

- Мьютексы сервера переживают отравление. Стандартный `lock().unwrap()` после
  паники в любой задаче ронял бы каждое следующее обращение — сервер уходил бы
  в лавину падений и переставал принимать подключения.
- Разбор картинок ограничен по размеру и памяти: пять мегабайт сжатого файла
  разворачиваются в гигабайты пикселей, и одна такая «бомба» убивала бы процесс
  вообще без сообщения.
- Паника в рабочем потоке не разбирает терминал: процесс от неё не умирает, и
  выбрасывать человека из переписки из-за одной битой картинки незачем. В
  журнал она при этом попадает.
- Если сетевая задача всё-таки упадёт, интерфейс скажет об этом вместо того,
  чтобы вечно показывать «подключаюсь».
- Опрос графических возможностей терминала не запускается, когда stdin или
  stdout не консоль: на Windows он в этом случае зацикливается и съедает ядро.
- Отдельный тест прогоняет отрисовку всех экранов на девяти размерах окна, от
  1×1 — ловит переполнение вычитания и выход за границы, из-за которых TUI и
  «вылетает».

## Размер сборки

Клиент — около 11 МБ. Внутри QUIC-стек с пробиванием NAT, разбор четырёх
форматов картинок и звук, так что совсем маленьким он быть не может, но
несколько решений его заметно ужимают:

- `opt-level = "s"` вместо `3`. Чат ничего не считает — он ждёт сеть и нажатия,
  поэтому разворачивание циклов и агрессивный инлайнинг здесь только весят.
- `lto = "fat"`. Собирается дольше, зато выбрасывает всё, что не позвали; при
  зависимостях такого размера это уже не считаные проценты.
- Криптография одна на всю сборку. По умолчанию `axum-server` притаскивает
  `aws-lc-rs` — C-библиотеку, которая компилируется отдельно, — хотя QUIC в
  туннеле уже использует `ring`. Провайдер выбран явно, второй бэкенд не
  собирается вовсе.
- Из iroh выключены `metrics` (счётчики, которые мы нигде не показываем) и
  `fast-apple-datapath` (ускорение сокетов macOS). `portmapper` оставлен
  намеренно: он просит роутер открыть порт и повышает долю прямых соединений
  вместо релея.

Вместе это дало 18,7 МБ → 10,7 МБ. `panic = "abort"` сюда намеренно не
добавлен, хотя он тоже ужимает: на раскрутке держится то, что паника в рабочем
потоке не убивает процесс, а превращается в сообщение в переписке.

## Сборка

```bash
cargo build --release
```

Получается два самостоятельных файла примерно по шесть мегабайт: `tui.exe` и
`server.exe`. Ни рантайма, ни установщика, ни внешних библиотек — веб-клиент,
TLS, декодеры картинок и звук лежат внутри. Достаточно и одного `tui.exe`: с
`--host` он и сервер, и клиент.

В профиле выпуска намеренно **не** включён `panic = "abort"`: на раскрутке
держится то, что паника в рабочем потоке не убивает процесс, а превращается в
строку в переписке.

## Тесты

```bash
cargo test --workspace
```

Сетевые тесты поднимают настоящий сервер на свободном порту и ходят на него
настоящим WebSocket-клиентом, включая проверки гонки за ник, реконнекта и
удаления опустевших комнат.

Вёрстку видно, не открывая терминал:

```bash
cargo test -p null_terminal --test preview -- --nocapture
```

Тест ничего не утверждает — он печатает все экраны (вкладки, переписку, окна
поверх, все четыре темы) буквами, чтобы их можно было оценить целиком. Отдельно
есть прогон отрисовки по девяти размерам окна от 1×1 до 200×60: он ловит ровно
тот класс падений, из-за которого клиент «вылетает» при сужении окна.

## Чего пока нет

История и файлы на диске (сейчас всё живёт в памяти сервера), звонки, личные
сообщения, пароль на комнату и деплой на VPS. Смена комнаты и ника работает переподключением под капотом — отдельного
протокольного сообщения для этого нет. Отправлять файлы из терминала нельзя:
показать результат он всё равно не сможет.
