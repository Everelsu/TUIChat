# Чат

Чат в локальной сети: сервер на Rust, клиент для терминала и веб-клиент для
телефона. Оба клиента говорят на одном протоколе — сервер не знает, кто на том
конце.

```
┌──────────────┐   WebSocket (JSON)   ┌──────────────┐   WebSocket (JSON)   ┌─────────────┐
│ TUI-клиент   │ ──────────────────── │    Сервер    │ ──────────────────── │ Браузер     │
│ (терминал)   │                      │  axum+tokio  │   он же отдаёт HTML  │ (телефон)   │
└──────────────┘                      └──────────────┘                      └─────────────┘
```

## Быстрый старт

Сервер (слушает `0.0.0.0:8080`, адрес меняется переменной `CHAT_ADDR`):

```bash
cargo run -p server
```

Терминальный клиент — ник спросит на экране входа:

```bash
cargo run -p tui
```

Можно и сразу, минуя экран входа:

```bash
cargo run -p tui -- --nick alice --room general
```

Веб-клиент: открыть в браузере `http://localhost:8080`. Ссылка вида
`http://localhost:8080/?room=rust` зовёт сразу в нужную комнату.

Команды в TUI (и `/help` внутри клиента):

| Команда | Что делает |
| --- | --- |
| `/join <комната>` | перейти в другую комнату |
| `/rooms` | показать живущие на сервере комнаты |
| `/nick <ник>` | сменить ник |
| `/send` | выбрать файл в обзоре; `/send <путь>` — отправить сразу |
| `/rec` | записать голосовое, повторно — отправить |
| `/host [порт]` | поднять свой сервер и позвать друга |
| `/color <цвет>` или `/color <ник> <цвет>` | свой или чужой цвет, `-` сбрасывает |
| `/play` | проиграть последнее голосовое, `/stop` — остановить |
| `/save [путь]` | сохранить последнее вложение на диск |
| `/view` | показать последнюю картинку прямо в терминале |
| `/open` | открыть последнее вложение внешней программой |
| `/clear` | очистить историю на экране |
| `/quit` | выход |
| `//текст` | отправить сообщение, начинающееся со слэша |

Интерфейс собран без рамок-коробок: шапка с комнатой, участниками и состоянием
связи, лента с группировкой сообщений одного автора, скруглённое поле ввода и
строка подсказок. Цвета заданы в RGB, поэтому терминалу нужен 24-битный цвет —
он есть в Windows Terminal, VS Code, iTerm2 и почти везде, кроме совсем старых
эмуляторов.

Клавиши:

| Клавиша | Что делает |
| --- | --- |
| `Enter` | отправить |
| `Tab` | дополнить команду в начале строки или ник, повторное — следующий |
| `Ctrl+O` | выбрать файл для отправки |
| `Ctrl+R` | ответить: стрелки выбирают сообщение, `Enter` подтверждает |
| `Ctrl+F` | поиск по истории, `Enter` и стрелки — по совпадениям |
| `↑` / `↓` | листать отправленное |
| `PgUp` / `PgDn`, колесо | прокрутка истории |
| `Ctrl+W` | стереть слово |
| `Ctrl+A` / `Ctrl+E` | в начало и конец строки |
| `Ctrl+U` / `Ctrl+K` | стереть до начала и до конца строки |
| `Esc` | закрыть картинку, поиск или цитату; иначе выход |

Перехват мыши нужен ради прокрутки колесом и ломает выделение текста — во всех
современных терминалах его возвращает `Shift` с зажатой мышью. Об этом сказано
и в самой справке: без подсказки это выглядит как поломка.

Сочетания работают и на русской раскладке. При ней `Ctrl+F` физически приходит
как «Ctrl+а», `Ctrl+R` — как «Ctrl+к», а `Ctrl+C` — как «Ctrl+с», то есть все
сочетания отваливаются ровно тогда, когда ими и пользуются: когда человек пишет
по-русски. Клиент приводит их обратно по раскладке ЙЦУКЕН.

При упоминании ника терминал подаёт звуковой сигнал: системных уведомлений
из TUI не показать.

## Картинки

В веб-клиенте картинку можно выбрать кнопкой `+`, вставить из буфера (`Ctrl+V`
после скриншота) или перетащить в окно. Подпись берётся из поля ввода, так что
картинка и комментарий уходят одним сообщением.

Из терминала файл отправляется командой `/send`: открывается обзор каталога,
файл выбирается стрелками, отсев по имени набирается прямо там. Каталог
запоминается — в следующий раз обзор откроется в нём же. Путь можно и написать
руками: `/send C:\фото\кот.png`.

Неподдерживаемые файлы в обзоре видны, но приглушены: прятать их хуже — человек
начинает искать, куда делся его файл. Годится и картинка, и готовое голосовое. Обратно вложение забирается командой `/save [путь]`: без
пути файл ляжет в «Загрузки» под своим именем.

Голосовое записывается командой `/rec`, повторное `/rec` останавливает запись и
отправляет её. Внизу при этом тикает счётчик секунд.

Пишется моно 16 кГц в wav: речи этого хватает с запасом, а пять мегабайт потолка
превращаются из тридцати секунд в две с половиной минуты. Wav выбран потому, что
браузеры играют его нативно, а opus нам не закодировать без C-библиотеки — то
есть записанное в терминале слышно везде, и это единственный формат, у которого
так получается.

В терминале картинка приходит строкой `[кот.png · 240 КБ]`. Команда `/view`
открывает её поверх переписки прямо в терминале, `Esc` закрывает; `/open`
отдаёт файл системному просмотрщику.

Если терминал умеет графику, картинки показываются **прямо в переписке**:
скачиваются сами и ложатся миниатюрой в десять строк под сообщением. Подпись
с именем и размером остаётся рядом, а `/view` открывает картинку во весь экран.

Миниатюры включаются в kitty и iTerm2. В них картинка привязана к ячейкам
буфера и при прокрутке двигается вместе с текстом почти бесплатно; sixel же
заставляет терминал перерисовывать графику на каждый сдвиг, и лента заметно
тормозит — поэтому там миниатюр по умолчанию нет. Включить или выключить их
принудительно можно настройкой `inline_images` в конфиге.

Без миниатюр остаётся строка `[кот.png · 240 КБ]` и `/view`; заодно ничего
лишнего не качается.

Клиент при запуске спрашивает у терминала, что тот умеет. Если поддерживается
графика — kitty, iTerm2 или sixel, — фотография показывается фотографией.
Название протокола видно в нижней рамке просмотра: если там «полублоки», значит
терминал графику не поддержал.

Запасной путь — полублоки: символ `▀` делит ячейку пополам, верхняя половина
красится цветом символа, нижняя — цветом фона, так что одна строка даёт два ряда
пикселей. Разрешение скромное, зато работает везде, где есть 24-битный цвет.

Опрос терминала делается один раз, до запуска чтения клавиатуры: он пишет
escape-последовательность и ждёт ответ из того же stdin. И только если по обе
стороны настоящий терминал — иначе на Windows опрос уходит в бесконечный цикл.

Скачивание работает по http. Если сервер запущен с `CHAT_TLS=1`, терминал
скажет об этом и предложит `/open`.

Ограничения: до 5 МБ на файл; картинки — jpeg, png, gif, webp, звук — webm, ogg,
mp4. Тип определяется по содержимому файла, а не по имени или заголовку запроса. SVG намеренно не
поддерживается: это XML, умеющий исполнять скрипты, а раздаются файлы с того же
адреса, что и сам чат.

Файлы лежат в памяти сервера, всего до 64 МБ; когда место кончается,
вытесняются самые старые. Перезапуск сервера стирает их вместе с историей.

## Список комнат

На экране входа под формой виден список комнат, которые сейчас живут на сервере,
с числом людей в каждой. Выбор — стрелками `↑`/`↓`, `Enter` заходит в
выделенную; `Tab` по-прежнему переключает поля формы, а `Ctrl+R` обновляет
список. В веб-клиенте комнаты показаны так же — тап по комнате подставляет её имя
в поле. Смысл простой: чтобы позвать друга, не нужно пересылать ему адрес-код в
другом мессенджере — он открывает клиент, видит комнату и заходит.

Список берётся запросом `GET /rooms` (обычный JSON) с того же адреса, что и
переписка. Пустых комнат в нём нет: комната на сервере живёт, только пока в ней
кто-то есть, поэтому показывается ровно то, куда сейчас можно зайти. Уже из чата
тот же список доступен командой `/rooms`, а перейти — `/join <комната>`.

Список показывает комнаты **одного** сервера. Чтобы люди видели друг друга «из
любой точки, где есть интернет», сервер должен быть доступен из интернета: это
общий hub на машине с публичным адресом (VPS или проброс порта), а клиент тогда
указывает на него полем «сервер». Два домашних компьютера за роутерами напрямую
друг друга не увидят — так устроен NAT, и обойти это без общего доступного узла
нельзя. В локальной сети всё работает без настройки.

## Разговор вдвоём без отдельного сервера

```bash
cargo run -p tui -- --host
```

То же самое делается из уже открытого клиента командой `/host` — перезапускать
ничего не нужно. Клиент печатает в переписку адрес, который можно переслать:
собеседник вставляет его в поле «сервер» на экране входа. Вставлять можно что
угодно узнаваемое — `192.168.1.5:8080`, `ws://192.168.1.5:8080/ws` или ссылку
на веб-клиент из браузера: клиент сам приведёт адрес к рабочему виду.

Порт меняется флагом `--port` или аргументом команды: `/host 9000`. Если он занят, клиент скажет об этом в обычном
терминале и не станет запускаться — молча уводить разговор на чужой сервер
хуже, чем отказаться.

Клиент поднимает сервер прямо в себе и печатает в переписку адрес, который
можно переслать собеседнику: он подключается через `--server ws://…`, а с
телефона открывает тот же адрес по http. Комната живёт, пока открыт терминал.

Отдельный процесс для разговора вдвоём — лишняя церемония: клиент и так умеет
всё, что нужно. Для постоянной комнаты сервер по-прежнему запускается сам по
себе.

## Звук

При упоминании ника клиент подаёт короткий сигнал. Он генерируется на месте, а
не берётся из файла: звуковой файл пришлось бы куда-то класть и как-то ставить
вместе с программой. Если звуковой карты нет, остаётся звоночек терминала.

`/play` проигрывает последнее голосовое прямо в клиенте, `/stop` останавливает.

**Важное ограничение.** Проигрываются wav, mp3, flac, vorbis и aac в mp4 —
всё, что умеет rodio. **Opus в этот список не входит**, а браузеры записывают
голосовые именно в него. Такое голосовое клиент честно откажется играть и
предложит `/open` — внешний проигрыватель с ним справится. Полноценная
поддержка требует libopus, то есть C-библиотеки в сборке, а от такой
зависимости мы уже отказались один раз ради chafa.

## Настройки

Клиент запоминает последний ник, комнату и адрес сервера после удачного входа —
запоминается то, что сервер принял, а не то, что ввели. Аргументы командной
строки эти значения перекрывают и ничего не перетирают.

Файл лежит там, где такие файлы принято искать: `%APPDATA%\tuichat\config.toml`
на Windows, `$XDG_CONFIG_HOME/tuichat/config.toml` или
`~/.config/tuichat/config.toml` на остальных.

```toml
server = "ws://192.168.1.5:8080/ws"
nickname = "alice"
room = "general"

[colors]
alice = "#d97757"
bob = "cyan"
```

Цвета можно править руками или командой `/color`. Названия понимаются на обоих
языках (`cyan`, `бирюзовый`), а хранятся как `#rrggbb`. Сломанный файл не мешает
запуску: клиент берёт значения по умолчанию.

Туда же, в `crash.log`, пишутся падения. В TUI стандартный вывод занят
интерфейсом, поэтому иначе сообщение о панике исчезает вместе с закрывающимся
экраном, и понять, что случилось, нельзя.

## «Печатает…»

Пока собеседник набирает сообщение, внизу вместо подсказки идёт строка
«bob печатает» с бегущими точками; в браузере — над полем ввода.

Сигнал одноразовый: отдельного «я перестал печатать» в протоколе нет, строка
гаснет сама через четыре секунды. Так не приходится думать про потерянные
отмены. Клиент шлёт сигнал не чаще раза в две секунды, а сервер отбрасывает всё
чаще раза в секунду — клиент с ошибкой не должен заливать этим комнату.

## Ответы на сообщения

В терминале `Ctrl+R` открывает выбор сообщения, стрелки ходят по репликам,
`Enter` подтверждает — над полем ввода появляется цитата, `Esc` её снимает.
В браузере достаточно щёлкнуть по нику (по всему сообщению — нельзя, иначе
не выделить текст мышью).

Клиент отправляет только идентификатор исходного сообщения; цитату сервер
собирает сам из истории комнаты. Иначе ничего не стоило бы приписать человеку
слова, которых он не писал. Если исходное сообщение уже вытеснено из истории,
ответ уходит без цитаты — терять из-за этого сам ответ было бы обидно.

## Голосовые

Кнопка `●` в веб-клиенте начинает запись, повторное нажатие отправляет её;
запись сама останавливается через две минуты. Формат выбирает браузер: Chrome
пишет webm, Firefox — ogg, Safari — mp4, сервер понимает все три.

Микрофон браузеры дают только по https, поэтому для записи с телефона нужен
`CHAT_TLS=1` — по `http://192.168.x.x` кнопка честно скажет об этом.

В терминале голосовое выглядит как `[голосовое.webm · 42 КБ]` и открывается
через `/open`.

## Установка на телефон

Открыть чат в браузере телефона и выбрать «Добавить на главный экран». Появится
отдельная иконка, приложение запустится без адресной строки, а когда сервер
недоступен — покажет «нет связи» вместо ошибки браузера.

Установка предлагается только по https (`CHAT_TLS=1`): без защищённого
соединения браузер не регистрирует service worker.

Кнопка `🔔` включает звук и уведомления при упоминании ника. Разрешение
запрашивается только по нажатию: непрошеный запрос браузеры показывают один
раз, и отказ потом не переиграть.

## HTTPS

По умолчанию сервер работает по http. Чтобы включить https:

```bash
CHAT_TLS=1 cargo run -p server
```

При первом запуске в каталоге `tls/` появится самоподписанный сертификат,
выписанный на `localhost` и на все локальные адреса машины. Браузер один раз
спросит подтверждение — это нормально для самоподписанного сертификата.
Удалите каталог, чтобы выпустить его заново (например, после смены сети).

Это понадобится, если захочется микрофон, камеру или уведомления: браузеры дают
их только в защищённом контексте, и по `http://192.168.x.x` они не работают
вообще.

## С телефона по Wi-Fi

Телефон и компьютер должны быть в одной сети. Узнать адрес компьютера:

```bash
ipconfig
```

Нужна строка «IPv4-адрес» вида `192.168.x.x`. Впрочем, сервер печатает нужный
адрес сам при запуске — строкой «с телефона». На телефоне открыть
`http://192.168.x.x:8080`, веб-клиент отдаёт тот же сервер, отдельно ничего
поднимать не надо.

Если страница не открывается, почти всегда дело в брандмауэре Windows: при
первом запуске он спрашивает, разрешить ли программе приём подключений, и надо
поставить галочку **частные сети**. Если окно уже было закрыто, разрешение
добавляется в «Защитник Windows → Брандмауэр → Разрешение взаимодействия с
приложением».

Для доступа из интернета нужен либо проброс порта на роутере, либо VPS с
публичным адресом. Протокол от этого не меняется — меняется только адрес,
который передаётся клиенту.

## Устройство

| Каталог   | Что там                                                        |
| --------- | -------------------------------------------------------------- |
| `common/` | типы протокола и проверка ввода — общие для сервера и клиентов  |
| `server/` | комнаты, рассылка, раздача веб-клиента                          |
| `tui/`    | терминальный клиент: `app` (состояние), `net` (связь), `ui`     |
| `web/`    | веб-клиент: HTML, CSS и JS без сборки и зависимостей            |

Файлы из `web/` вшиты в бинарь сервера через `include_str!`: сервер запускается
из любого каталога и переносится одним файлом. Цена — после правки вёрстки
нужна пересборка сервера.

## Протокол

JSON поверх WebSocket на `/ws`. У каждого сообщения есть поле `type`.

Клиент → сервер: `join`, `chat`, `leave`, `ping`.
Сервер → клиент: `welcome`, `user_joined`, `user_left`, `chat`, `error`, `pong`.

Файлы по сокету не ходят: `POST /upload?name=<имя>` с телом-байтами возвращает
описание вложения, и в `chat` едет только его `attachment` — идентификатор.
Имя, размер и тип клиент не сообщает: их сервер знает сам, иначе подпись под
чужой картинкой подделал бы кто угодно. Отдаётся файл по `GET /media/<id>`.

Что стоит знать, если писать третий клиент:

- Первым сообщением обязан быть `join`, иначе через 10 секунд сервер закроет
  соединение. На неудачный `join` (занятый ник) соединение не рвётся — можно
  спросить у человека другой ник и попробовать снова.
- В ответ на `join` приходит `welcome` с последними репликами комнаты. У каждой
  есть `id`: после переподключения история накладывается на уже показанное, и
  клиент обязан отбрасывать дубли по нему. История живёт, пока в комнате есть
  хоть кто-то, — опустевшая комната удаляется вместе с перепиской.
- `error` несёт машиночитаемый `code`. `nickname_taken`, `invalid_nickname` и
  `invalid_room` переподключением не лечатся, остальные — временные.
- Время (`ts`) ставит сервер, в UTC и миллисекундах. Переводить в местное —
  забота клиента.
- Сообщения однострочные: переводы строк сервер схлопывает в пробелы,
  управляющие символы вырезает.
- Простаивающее соединение рвут роутеры молча, поэтому клиенты раз в 30 секунд
  шлют `ping` и ждут `pong`.

## Устойчивость

Что сделано, чтобы клиент и сервер не падали:

- Мьютексы сервера переживают отравление. Стандартный `lock().unwrap()` после
  паники в любой задаче ронял бы каждое следующее обращение — сервер уходил бы
  в лавину падений и переставал принимать подключения.
- Разбор картинок ограничен по размеру и памяти: пять мегабайт сжатого файла
  разворачиваются в гигабайты пикселей, и одна такая «бомба» убивала бы процесс
  вообще без сообщения.
- Паника в рабочем потоке не разбирает терминал: процесс от неё не умирает, и
  выбрасывать человека из переписки из-за одной битой картинки незачем. В
  журнал она при этом попадает.
- Если сетевая задача всё-таки упадёт, интерфейс скажет об этом вместо того,
  чтобы вечно показывать «подключаюсь».
- Опрос графических возможностей терминала не запускается, когда stdin или
  stdout не консоль: на Windows он в этом случае зацикливается и съедает ядро.
- Отдельный тест прогоняет отрисовку всех экранов на девяти размерах окна, от
  1×1 — ловит переполнение вычитания и выход за границы, из-за которых TUI и
  «вылетает».

## Сборка

```bash
cargo build --release
```

Получается два самостоятельных файла примерно по шесть мегабайт: `tui.exe` и
`server.exe`. Ни рантайма, ни установщика, ни внешних библиотек — веб-клиент,
TLS, декодеры картинок и звук лежат внутри. Достаточно и одного `tui.exe`: с
`--host` он и сервер, и клиент.

В профиле выпуска намеренно **не** включён `panic = "abort"`: на раскрутке
держится то, что паника в рабочем потоке не убивает процесс, а превращается в
строку в переписке.

## Тесты

```bash
cargo test --workspace
```

Сетевые тесты поднимают настоящий сервер на свободном порту и ходят на него
настоящим WebSocket-клиентом, включая проверки гонки за ник, реконнекта и
удаления опустевших комнат.

## Чего пока нет

История и файлы на диске (сейчас всё живёт в памяти сервера), звонки, личные
сообщения, пароль на комнату и деплой на VPS. Смена комнаты и ника работает переподключением под капотом — отдельного
протокольного сообщения для этого нет. Отправлять файлы из терминала нельзя:
показать результат он всё равно не сможет.
